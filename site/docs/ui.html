The UI Layer

high.gfx.* (see Libraries) can draw a rectangle. That is enough for a chart and not enough for a program with a toolbar, so the UI layer sits on top of it and decides where things go and how they move.

The UI layer is a window system, not a web page. It has frames that own other elements, panes that dock to an edge, and tweens that are objects rather than one-shot calls. src/bx_ui.c implements it; the commands below are the whole surface.

TWO SPELLINGS

Every command answers to two forms, and they mean the same thing:

ui.new|sidebar|pane|root

The dotted form reads like the rest of the libraries. The bar form reads like a script, where | separates arguments anyway. Use whichever is clearer in the line you are writing.

ELEMENTS HAVE NAMES

An element is identified by a string id, not by a number.

ui.init
ui.new|root|frame
ui.new|title|label|root
ui.set|title|text|BoxedLANG
ui.get|title|text|now
say $now

Names may use letters, digits, and _, ., and -, up to 31 characters. An id is interned on first use, which means ui.new with an id that already exists is refused instead of quietly making a second element with the same name:

ui new: bad id 'title' (max 31 chars, a-zA-Z0-9_.-) or id already exists

That is deliberate. In a window system, two elements answering to the same name is not a feature; it is a bug that shows up later as the wrong thing moving.

The element kinds are frame, pane, panel, button, label, text, textbox, slider, checkbox, radio, dropdown, image, icon, shape, list, listitem, tabs, tab, split, scroll, grid, stack, progress, spinner, canvas, tree, menu, menuitem, toolbar, statusbar, sidebar, modal, tooltip, and tween. ui.kinds.list prints the names as the binary knows them.

Anything the list does not name is still accepted, and becomes a config object: a container with a bag of values that you set and tune like anything else. This is the escape hatch for a look that has no element yet.

ui.new|theme.accent|my-accent-style

FIELDS

ui.set|ID|field|value writes a field, ui.get|ID|field|BOX reads one:

ui.set|title|w|240
ui.set|title|h|32
ui.set|title|color|#d7e2ee
ui.get|title|w|w
say $w

The geometry fields are x, y, w, and h. minw and minh are floors that a layout will not go below. visible hides an element without removing it. text and value are its two strings. color and alpha describe its fill. gap, padx, and pady are spacing. align and justify place children inside a layout. z decides who is on top. style and theme name a theme, and columns sets the column count for a grid.

LAYOUT

A frame arranges its children according to its layout:

| Layout | Children are placed | | --- | --- | | none | where their x and y say | | row | left to right | | column | top to bottom | | grid | in a grid of columns columns | | stack | all at the same origin, ordered by z | | wrap | left to right, wrapping at the frame's width |

ui.set|toolbar|toolbar|layout|row
ui.set|toolbar|gap|8
ui.set|toolbar|padx|12
ui.layout|toolbar

ui.layout|FRAME runs the arrangement and prints the result, which makes it easy to see what changed. ui.list shows every element with its geometry, and ui.attach|FRAME|ID... and ui.detach|FRAME|ID change who owns whom.

DOCKING

A pane can dock to an edge instead of taking a position.

ui.new|sidebar|pane|root
ui.set|sidebar|w|200
ui.set|sidebar|dock|left
ui.dock|sidebar

The docks are none, left, right, top, bottom, center, and fill. A pane sizes itself against its parent frame when it has one, and against the screen when it does not, which is why a sidebar nested in a window is sized by the window rather than by the display.

FRAMES

Time moves in two ways, and the difference matters.

ui.frame.once advances every running tween by the wall clock, using the same fixed step the interpreter uses elsewhere. It is the right choice for a script.

ui.frame.once

ui.frame.step|SECONDS advances by an exact amount instead. That is what makes the tests in tests/ui.bx give the same answer on any machine: a tween of 0.4 seconds is halfway after exactly one 0.2 second step, whether the machine is fast or slow.

ui.frame.step|0.2

ui.frame.fps|N sets the frame rate used by once. Loop frame inside a program that also needs to do other work, and the tweens keep moving without blocking anything.

TWEENS

A tween changes one property of one element over time, and it is an object you name.

ui.tween|sl|sidebar|x|0|-200|0.4|ease-out
ui.frame.step|0.2
ui.get|sidebar|x|half
say $half

The form is ui.tween|ID|TARGET|PROP|FROM|TO|DURATION|FN. The id is the tween's name, and two tweens with the same id are the same tween, which is how a moving element stays in one slot instead of drifting into a new one each time it is touched.

Two shorthands help when a tween is nearly over: ui.tween|ID|to|VALUE finishes it at a new destination, and ui.tween|ID|cancel stops it where it is.

Retargeting is the behaviour worth knowing. A running tween that gets a new target continues from where it is, not from where it started:

x=-37.854  after one 0.1s step
x=-124.09  after two
x=-153.499 after three
x=-160     after four  (0.4s done)
x=-39.5183 after retargeting to -40 from x=-160

That is what makes a pane slide follow a drag instead of snapping to the beginning every time the pointer moves.

ui.tween.list shows the running tweens and how far along they are.

EASING

Linear motion looks mechanical, because it is. Everything else is a way of spending time differently.

ui.tween|sl|sidebar|x|0|-200|0.4|spring

The built-ins are linear, ease-in, ease-out, ease-in-out, spring, and bounce, with ease-in-out as the default. linear is exactly y = mx + b, which is a fine thing to be, since a tween is just a function of time and linear is the first one to write down.

A new curve is four numbers for a cubic bezier, the same control points CSS and iOS use, or two for a line:

ui.tweenfn.set|swift|0.25|0.1|0.25|1
ui.tweenfn.set|ramp|0.5|1

ui.tweenfn.list prints what is defined. To look at a curve without running an animation, sample it:

ui.ease|swift|0.5|half
say $half

That prints the samples and puts the last one in the box:

ease swift: 0.5->0.8024
0.802403

Enough to check that a curve is shaped the way you meant it, before anything moves.

SWITCHING AND CLOSING

ui.switch|PANE brings a pane to the front. ui.close|ID removes an element and detaches it from its parent, which is why closing a pane leaves its frame's child count correct instead of leaving a hole.

WHAT IS NOT HERE YET

The layer computes geometry and motion; it does not yet draw. Wiring ui.* into high.gfx.render so the tree paints itself, adding hit testing so elements can be clicked, and building out the icon set as bxvg documents are all still ahead. What is here now is the part that is awkward to retrofit: names, structure, and time.
