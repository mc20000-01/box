UI

The UI toolkit is a ui command family with 134 element kinds, a layout engine, theming, tweens, and a small vector document system of its own.

Two argument spellings, and the trap between them

Everything below accepts either spelling:

ui.new|alpha|frame
ui|new|beta|frame

They are the same command. But the dotted form takes its arguments space-separated and the bar form takes them after a |, and mixing them silently passes nothing:

ui.vg add|ring|circle|40|40|30

That does not work and does not say so. It is parsed as the command ui.vg with the single argument add|ring|circle|40|40|30, and the vg handler checks for reset, finds add|ring..., and does nothing.

Use the dotted form with spaces for everything except ui.vg, where the bar form is what works.

lib load|gfx
high.gfx.fbsize 400|300
ui init
ui|vg|reset
ui|vg|size|200|100
ui|vg|add|ring|circle|40|40|30|#4fd6c4
ui|vg|draw|0|0|200|100
end

That is a complete program, and it is the shortest one in this repository.

Starting

lib load|gfx
high.gfx.fbsize 400|300
ui init
end

Output is ui: init ok.

ui init must come after lib load|gfx and before the first jump. The UI draws into a framebuffer, so the graphics library has to be there first, and a ui command on a line after the first jump never runs.

Elements

lib load|gfx
high.gfx.fbsize 400|300
ui init
ui.new|root|frame
ui.set|root|w|400
ui.set|root|h|300
ui.new|btn|button|root
ui.set|btn|text|click me
ui.set|btn|x|20
ui.set|btn|y|40
ui.set|btn|w|120
ui.set|btn|h|36
ui.get|btn|text|t
say the button says $t
ui.list
end

Output:

the button says click me
ui elements (2):
  root           frame     parent=-            x=0 y=0 w=400 h=300
  btn            button    parent=root         x=20 y=40 w=120 h=36

ui.new|ID|KIND|PARENT makes one, ui.set|ID|FIELD|VALUE changes it, and ui.get|ID|FIELD|BOX reads it back. ui.list prints the tree, ui.hit and ui.focus inspect it, and ui.close removes one.

Ids are short strings, not numbers: root, btn, sidebar. They may hold letters, digits, _, - and ., up to 31 characters.

The 134 kinds

ui kinds|list prints all of them. Grouped by what they are for:

Structure — frame, pane, panel, panel2, group, groupbox, window, dialog, card, sidebar, toolbar, toolbelt, toolbox, statusbar, header, footer, nav, navbar, menu, menusep, drawer, flyout, split, splitpane, splitter, stack, tile, accordion, banner, grid, list, tree, tween, bar, bargroup, a, acc

Text — text, label, quote, blockquote, code, codeblock, kbd, key, link, legend, labelgroup, breadcrumb, crumbs, tag, chip, badge, hint, help, notice, alert, empty, placeholder, skeleton, spinner, loading

Input — button, btn, iconbtn, input, textbox, field, fieldbox, combo, combobox, select, dropdown, checkbox, check, radio, switch, toggle, togglegroup, segmented, slider, knob, dial, gauge, stepper, pager, pagination, color, swatch

Data — table, row, cell, th, td, tr, listitem, item, menuitem, navitem, meter, progress, rating, stars, thumb

Media — image, icon, avatar, canvas, thumbnail, shape

Feedback — tooltip, flyout, modal, scrim, overlay, snackbar, toast, pill, dot, divider, hr, rule, separator, gap, spacer, blank, scroll, scrollbar, well, spinnerbox

Navigation — tab, tabs, status

The grouping above is mine for readability; the order ui kinds|list prints is alphabetical.

Anything not in the list is accepted as a custom element: a free-form container with a column layout, 8px padding and a 6px gap, whose fields you can set and tune. That is a feature, not a fallback — it is how you get a layout the 134 do not cover without touching C.

Themes

A theme is bracketed, dot-separated, and all six fields required, in the order c h r t x b:

lib load|gfx
high.gfx.fbsize 400|300
ui init
ui.new|root|frame
ui.set|root|theme|[c#2a9d8f.h#e9f5f0.r4.t%90.x#000000.b#ffffff]
ui.set|root|w|400
say set it
end

| tag | field | notes | |---|---|---| | c | primary | the main accent | | h | highlight | for the thing under the pointer | | r | rounding | corner radius in pixels | | t | alpha | 0-100, t%90 or t90 | | x | tertiary | muted text | | b | quaternary | borders and dividers |

A partial theme is rejected: theme|c#fff reports a bad value and leaves the element unchanged, which reads like a crash and is not one. It is a -1 from the parser, and all six are required because order is part of the format.

theme is write-only. ui get|ID|theme reports an unknown field, so keep the string you used in a box if you need to read it back.

ui.tweenfn and ui.ease change how values move between themes; see Tweens.

Layout and docking

A frame is the root. Everything else names it as a parent and is laid out inside it.

lib load|gfx
high.gfx.fbsize 400|300
ui init
ui.new|root|frame
ui.set|root|w|400
ui.set|root|h|300
ui.new|main|pane|root
ui.set|main|w|300
ui.new|side|pane|root
ui.set|side|w|100
ui.dock|main|left
ui.dock|side|right
ui.layout|root
ui.list
end

Output:

ui: docked main -> x=0 y=0 w=300 h=0
ui: docked side -> x=0 y=0 w=100 h=0
ui: layout applied to root (2 children)
ui elements (3):
  root           frame     parent=-            x=0 y=0 w=400 h=300
  main           pane      parent=root         x=0 y=0 w=300 h=0
  side           pane      parent=root         x=0 y=0 w=100 h=0

ui.layout|FRAME runs the layout pass. ui.dock|ELEMENT|SIDE pins one to an edge. ui.attach takes the frame first — attach|FRAME|CHILD|CHILD — and moves the named children into it. Getting this backwards re-parents the frame into its own child, and nothing complains, so it is worth remembering which way round it is. ui.detach|FRAME|CHILD reverses it, and ui.switch|PANE moves between panes.

Recommended way to size things: set w and h on the root frame, dock the panes, and let the layout pass do the arithmetic. Setting x and y on a child fights the layout engine, and the engine wins.

Input

Nothing in ui reads a device. A platform, a script or a test all feed the same calls, which is why the UI can be driven without a window:

lib load|gfx
high.gfx.fbsize 400|300
ui init
ui.new|root|frame
ui.set|root|w|400
ui.set|root|h|300
ui.new|btn|button|root
ui.set|btn|text|ok
ui.set|btn|x|20
ui.set|btn|y|40
ui.set|btn|w|100
ui.set|btn|h|32
ui.pointer|30|50|down
ui.focus|btn
ui.press|btn|1
ui.get|btn|pressed|p
say pressed=$p
ui.pointer|30|50|up
end

Output is pressed=1.

pointer|X|Y|ACTION moves and clicks, key|KEY|ACTION types, and focus|ID|next|prev moves focus. press|ID|0|1, select and hit are the direct ways to drive state from a script or a test. input|release drops the held state so one click does not repeat forever.

Tweens and easing

A tween moves one property from one value to another over a duration. The signature is:

ui tween|ID|TARGET|PROP|FROM|TO|DURATION[|FN]

| field | meaning | |---|---| | ID | arbitrary name for this tween | | TARGET | element id to animate | | PROP | property name (x, y, w, h, opacity, ...) | | FROM | start value | | TO | end value | | DURATION | seconds, float | | FN | optional easing function (ease, ease-in, ease-out, ease-in-out, linear, bounce, elastic) |

lib load|gfx
high.gfx.fbsize 400|300
ui init
ui.new|root|frame
ui.set|root|w|400
ui.new|box|panel|root
ui.set|box|x|0
ui.tween|slidein|box|x|0|200|0.5|ease
ui.frame|step|0.25
ui.get|box|x|x1
ui.frame|step|0.25
ui.get|box|x|x2
say after one step $x1, after two $x2
ui.tween|list
end

Use ui frame step SECONDS, not ui frame once. A fixed delta gives the same answer on a fast machine and a slow one, which is the difference between a test that passes everywhere and one that passes on yours.

ui.tween|ID|to|VALUE retargets mid-flight, ui.tween|ID|cancel stops it, and ui.tween|list shows what is running. ui.tweenfn|list and ui.ease|FN|... cover the easing curves.

ui.vg, the vector document

ui.vg is a small vector document system living beside the widget tree. It is a separate document with its own shapes and frames, and it renders into the same framebuffer.

Remember the bar form. Every ui.vg command here uses |.

lib load|gfx
high.gfx.fbsize 400|300
ui init
ui|vg|reset
ui|vg|size|320|200
ui|vg|bg|#101820
ui|vg|add|panel|rect|10|10|300|180
ui|vg|set|panel|fill|#2a9d8f
ui|vg|add|dot|circle|160|100|40
ui|vg|set|dot|fill|#e76f51
ui|vg|list
ui|vg|draw|0|0|320|200
end

Output:

ui vg: reset to 24x24
ui vg: document is 320x200
ui vg: background #101820
ui vg: added panel as shape 1 (rect)
ui vg: panel.fill = #2a9d8f
ui vg: added dot as shape 2 (circle)
ui vg: dot.fill = #e76f51
ui vg: 320x200, 2 shape(s), 0 frame(s)
ui vg: drew 2 shape(s)

Commands

| command | what it does | |---|---| | vg|reset | empty document, back to 24x24 | | vg|size|W|H | set the document size | | vg|bg|#hex | background color | | vg|load|BOX\|file\|PATH | read a .bxvg or an .svg | | vg|dump|BOX | write the document back out, into a box | | vg|svg\|file\|PATH | write SVG to a path | | vg\|svg\|BOX | SVG text into a box | | vg|add\|NAME\|TYPE\|... | add a shape | | vg\|set\|NAME\|FIELD\|VALUE | change one | | vg|list | every shape with its geometry | | vg\|draw\|X\|Y\|W\|H | render into the framebuffer | | vg\|ppm\|PATH\|X\|Y\|W\|H | render and write an image | | vg\|frame\|add\|NAME\|FROM\|COUNT | a frame showing a shape range | | vg\|frame\|NAME | show that frame | | vg\|frame\|next\|0 | next or frame 0 | | vg\|frame\|list | every frame | | vg\|frame\|anim\|FPS | advance on a timer | | ui.vg step | advance by a fixed delta |

The six shape types are rect, circle, ellipse, line, poly and path. An unknown type is refused, and the message says so.

lib load|gfx
ui init
ui|vg|reset
ui|vg|add|a|rect|5|5|40|20
ui|vg|add|b|ellipse|50|5|20|10
ui|vg|add|c|line|0|0|80|40
ui|vg|add|d|poly|0,0 10,0 10,10
ui|vg|add|e|path|M0 0 L10 10
ui|vg|list
end

The set fields are x, y, w, h, fill, stroke, sw, opacity, closed, name and type. sw is the stroke width, not stroke_w, and an unknown field is refused with the list of real ones.

fill none and stroke none turn that paint off, which is how you get an outline without a fill.

SVG in and out

lib load|gfx
ui init
ui|vg|reset
ui|vg|size|100|60
ui|vg|add|a|rect|5|5|40|20
ui|vg|set|a|fill|#ff8800
ui|vg|svg|file|.build/shape.svg
end

writes:

<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 100 60">
<rect x="5" y="5" width="40" height="20" fill="#ff8800" stroke="#ffffff" stroke-width="2" stroke-linecap="round" stroke-linejoin="round"/>
</svg>

Reading it back is ui|vg|load|BOX|file|PATH. The loader sniffs the content rather than trusting the extension, so an .svg under any name imports.

Frames

lib load|gfx
ui init
ui|vg|reset
ui|vg|add|a|rect|5|5|40|20
ui|vg|add|b|circle|60|5|15
ui|vg|frame|add|shapes|0|2
ui|vg|frame|list
ui|vg|frame|shapes
end

Output:

  frame 0 shapes      0..1  (showing)
ui vg: frame 0 'shapes'

FROM|COUNT is a range into the shape list, and a range past the end of the document is refused rather than stored as a frame that would show nothing.

Building a spec from a file

ui spec and ui build move a whole layout as text rather than as a long list of new and set lines. ui.spec|BOX dumps the whole tree into a box:

lib load|gfx
ui init
ui.new|root|frame
ui.new|btn|button|root
ui.set|btn|text|ok
ui.spec|doc
say [$doc]
end

Output:

[id=root kind=frame
id=btn kind=button text=ok parent=root
]

(ui spec also writes a one-line summary to stderr, which is why this example is marked no-stderr.)

ui build|BOX reads it back, and ui build|file|PATH reads it from disk, so a layout can be edited as a file and built without the script mentioning any of it. This is the recommended way to build anything with more than a handful of elements: the tree stays out of the script, and the file can be changed without touching code.

Recommended way to structure a UI

Three habits, in the order they start to matter.

Build the tree from new and set, then lay it out once. Creating and measuring in the same pass produces positions that are one frame stale.

Drive the input, never the state. ui.press|btn|1 rather than setting a pressed flag, ui.focus|btn rather than setting a focus index. The commands run the same handlers the platform does, so the two cannot drift apart.

Step by a fixed delta. ui frame step 0.016 in a test, ui frame once only in something with a real clock. Everything else in this repository's tests does this, and it is why the numbers are the same everywhere.
